## Why

The project audits its source tree carefully and its artefact not at all.

`cargo audit` reads `Cargo.lock`. That tells you whether the tree you are
looking at has a known-vulnerable dependency; it tells you nothing about a
binary somebody downloaded six months ago. There is currently no way to point a
tool at `adocpdf` and ask what went into it. For a program that embeds an entire
layout engine and carries two knowingly tolerated advisories in
`.cargo/audit.toml`, that is the wrong asymmetry.

Two smaller things are unfinished in the same direction. `[profile.release]`
contains exactly one line, `lto = "thin"`, and there is no `[profile.dev]`
section at all — so every test run recompiles Typst unoptimised. And
Conventional Commits are mandated twice, in `AGENTS.md` and in
`openspec/config.yaml`, and checked by nothing, which means the format holds
only as long as everyone remembers it.

## What Changes

- **The shipped binary carries its own dependency manifest.**
  `cargo-auditable` embeds it at build time, so `cargo audit bin adocpdf` works
  on the artefact rather than on the tree it came from.
- **A CycloneDX SBOM is produced as a release artefact**, generated by
  `cargo-cyclonedx` from the lockfile.
- **The release profile is completed** — `codegen-units` and `strip` decided on
  their merits, and `panic = "abort"` explicitly rejected rather than silently
  omitted, since a reader should be able to tell a decision from an oversight.
- **The dev profile stops rebuilding the layout engine unoptimised**, by raising
  `opt-level` for dependencies only. The improvement is expected but has **not
  been measured**; measuring it is a task, and if it turns out not to help, the
  setting comes back out.
- **Conventional Commits are enforced in CI**, on pull requests, where the
  check cannot be skipped.
- **`CHANGELOG.md` is generated from that history** by `git-cliff`, which is the
  return on having enforced the format.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. `.openspec.yaml` sets `skip_specs: true`.

## Non-goals

- **Publishing to crates.io.** `[workspace.lints]` allows
  `clippy::cargo_common_metadata` precisely because these crates are not
  destined for the registry, with the reasoning written out in `Cargo.toml`.
  Nothing here revisits that.
- **Binary distribution.** `cargo-dist`, release archives, installers and
  checksums are a distribution story that presumes users. There are none yet.
- **Cross-platform release matrices.** `bootstrap-repository` already limits CI
  to `ubuntu-latest` and says why; this change does not widen it.
- **Version-bump automation.** `release-plz` and `cargo-release` decide *when* to
  release and what the next version is. That is a policy question for a project
  with a release cadence.
- **Reproducible binary builds.** Making two machines produce byte-identical
  *binaries* — `--remap-path-prefix`, `SOURCE_DATE_EPOCH` — is a real goal and a
  separate one. See `design.md` D7 for why it is not the same as this project's
  existing determinism requirement.
- **Benchmarks.** The dev-profile change is measured by build wall-clock, not by
  a benchmark suite; `behavioural-testing` records why there is no benchmark
  suite to lean on.

## Ordering

This change depends on **`bootstrap-repository`** and cannot usefully be applied
before it, for two independent reasons:

1. The CI jobs here need `.github/` to exist.
2. `committed` and `git-cliff` both read commit history. Against the current
   repository — verified to have zero commits — a commit-message linter has
   nothing to lint and a changelog generator has nothing to summarise.

`behavioural-testing` is independent of this change; the two may be applied in
either order.

## Impact

**Architectural layers: none.** No crate under `crates/` is touched. No entry
in `architecture.toml` changes, and no crate manifest gains a dependency.

**Build configuration changes for every developer.** The `[profile.dev]` edit
alters how dependencies compile locally — a longer first build in exchange for
faster test runs. This is the one change here that a contributor will feel
daily, which is why it is measured rather than asserted.

**One interaction to verify, not assume.** `strip` and `cargo-auditable` both
act on the produced binary — one removing content, the other adding it. Whether
stripping removes the audit data is treated as unverified and confirmed
empirically; see `design.md` D3.

**Tooling, not dependencies.** `cargo-auditable`, `cargo-cyclonedx`,
`git-cliff` and `committed` are developer tools. Whether `cargo-auditable`
alters the dependency graph of the binary it builds is checked rather than
assumed, since `deny.toml`'s allow-list and the architecture guard both have an
opinion if it does.

**Determinism is unaffected.** The requirement is that a document plus an
injected date produce byte-identical PDF output. Nothing here touches that path.
